## 实现与技术栈

“技术栈”是实现软件所组合使用的语言、框架、运行时和工具。轻传把工作分成三部分：浏览器负责界面，本地服务负责配对与文件通道，构建工具把源码整理成可运行文件。

| 部分 | 技术 | 职责与选择理由 |
| --- | --- | --- |
| 页面 | TypeScript、React、手写 CSS | 同一界面适配电脑与手机，管理独立的收发状态 |
| 本地服务 | Node.js 内置 HTTP、内存 SQLite | 提供页面、会话和下载入口，无需另装数据库 |
| 文件通道 | WebSocket、`ws` | 与页面复用同一 TCP 端口，支持双向传输 |
| 内容校验 | SHA-256、WebCrypto / `@noble/hashes` | 校验文件内容，兼容局域网 HTTP 下缺少部分浏览器接口的情况 |
| 二维码与图标 | `qrcode`、`lucide-react` | 配对扫码和界面图标 |
| ZIP | `fflate` | 将多个原图合为一个下载任务，减少逐张确认 |
| 构建与发行 | Vite、esbuild | 构建静态页面、合并服务端依赖，发行时不携带开发工具 |

文件以 64 KiB 分块发送，控制发送缓冲；接收端完整校验后返回 ACK，发送端才显示送达。两端流状态和进度独立。HTTP 下载提供附件响应、中文文件名、HEAD / Range 和受限内存缓存；具体数据边界见[使用说明](使用说明.md#数据与使用边界)。

## 环境与运行

需要 Node.js ≥ 22.18.0、npm 和现代浏览器。便携包携带的 Node 22.23.5 已完成本地验证。

```sh
npm ci
npm run check
npm run build
npm start
```

完整配对与传图必须启动本地服务，不能只打开 `index.html`。`npm run dev` 用于调试前端界面；本地服务默认端口为 4317，可在 PowerShell 中更改：

```powershell
$env:PORT = '4318'
npm start
```

## 检查

先启动本地服务，再运行浏览器检查。浏览器检查使用本机 Microsoft Edge：

```sh
npm run check
npm test
npm run test:browser
```

检查覆盖配对和权限、双向及同时发送、文件内容一致、单张 / 多张 / ZIP 下载、原图新页、同名文件、断开和重新配对、HTTP Range / HEAD、缓存过期和容量限制。浏览器模拟手机宽度并禁用 WebRTC / Blob 下载，不能代替真实手机验证。

`tests/photo-removal.mjs` 额外检查两端发送 / 接收列表的单张移除、撤销后的顺序与状态、图片资源释放、移除后的 ZIP 内容、传输期间禁用操作及清空列表的行为。

## 构建发行包

在 Windows x64 执行：

```sh
npm run package:portable
npm run package:source
```

输出位于 `release/` 的独立子目录，每次构建保留自己的结果。可用 `-- --output <目录>` 指定位置。

- **源码包**：源码、依赖清单和文档，供开发者安装依赖后使用。
- **便携包**：构建后的网页、合并后的服务端、数据库结构、运行时、启动入口及第三方许可，供普通用户解压使用。

如需指定 Windows x64 Node，可设置 `QINGCHUAN_NODE_EXE`，对应许可文本用 `QINGCHUAN_NODE_LICENSE` 指定。构建脚本优先使用项目维护者的 `.runtime/node.exe`，其次使用当前 Node。

开发目录里的 `node_modules`、运行时、日志、缓存和输出包均不提交到仓库。当前源码已移出不用的框架、云端模拟器、图片处理和 UI 模板依赖。便携包剩余的大头是随附运行时，以换取普通用户无需安装环境。

本地独立目录验证已通过，尚未完成另一台干净 Windows 机器、签名 / 安装包和其他桌面平台的发行验证。
